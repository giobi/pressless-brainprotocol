I — What it is

Not a framework.
A convention.

Brain Protocol defines how an AI agent's memory should be organized on disk. No databases, no vector stores, no proprietary formats. Just directories and markdown files, the same way code lives in a git repo.

A brain is a repository. Everything the agent knows — people, projects, tasks, decisions, history — lives in structured markdown with frontmatter metadata. Boot, read, work, commit. Repeat.

"If your agent's memory can't be opened in a text editor, it isn't yours."

1

Plain text only

Every piece of memory is a readable markdown file. Open it in any editor, grep it, version it. You own the data.

2

Git is the database

Memory has history. Diff two sessions, revert a bad decision, audit exactly what the agent changed and when.

3

Frontmatter metadata

Machine-readable context on every file: type, tags, relationships, timestamps. Enough structure for reasoning, not so much it becomes a burden.

4

LLM-agnostic

Claude, Gemini, GPT, Mistral — any model that can read a file speaks Brain Protocol. No SDK. No API key required.

II — Structure

Six directories.
One coherent memory.

wiki/ Entities — people, companies, projects, technologies, domains. The agent's knowledge graph.
diary/ Temporal log. What happened, when, in what context. The agent's autobiographical memory.
todo/ Open tasks tracked in structured markdown. The agent knows what needs doing.
inbox/ Incoming items waiting to be processed. Email threads, notes, signals from external systems.
boot/ System configuration: identity, personality, tools, protocols. Loaded at session start.
tools/ API wrappers, automation scripts, integration code. What the agent can do, not just what it knows.
